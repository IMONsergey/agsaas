# AGSaaS: пакет доработок 01

Основание: согласованный [бэклог из 40 блоков](agsaas-hardening-backlog.md).
Начальная ревизия: `d95ffa247817c23d855ba178de32bfc987f2c7c1`.
Это законченный проверяемый пакет, а не заявление о завершении всего продукта.

## Реализовано

### Финансовые запросы

- Счета, проекты и теги агрегируются отдельно. Их объединение больше не размножает суммы и счётчики клиентов.
- Доход и задолженность списка клиентов приведены к базовой валюте команды. Если она не настроена, допустима только одна финансовая валюта всей команды.
- Неизвестный курс/валюта/сумма делает соответствующий показатель отсутствующим, а не правдоподобным частичным итогом. Существующий интерфейс показывает `-`.
- Выровнены границы команды для дочерних записей; сортировка имеет стабильный ID tie-breaker, неизвестные суммы идут последними.
- Цифровой префикс больше не отключает поиск клиентов; проверяются также email, billing email, VAT number и external ID.
- Налоговая сводка использует приоритет: явный `taxAmount` (включая ноль), собственная ставка, ставка категории. Фиксированный налог переводится в ту же валюту, что и сумма операции.

### Импорт CSV

- Строгий разбор RU/US сумм, обычных/неразрывных пробелов и календарных дат; неоднозначные разделители и даты требуют явного выбора.
- `parseProfile` действительно передаётся из существующих Settings в preview, API, BullMQ и worker. Поддержаны `auto`, day/month-first и decimal comma/dot.
- Проверка исходных цифр и границ `numeric(10,2)` выполняется до записи: без молчаливого округления или переполнения БД.
- Счётчик одинаковых операций действует на весь файл, включая границы parser chunks и DB batches. Первая операция сохраняет legacy ID, последующие получают стабильный порядковый суффикс.
- Устранено зависание paused Papa parser при асинхронном отказе записи; malformed/header-only CSV завершаются ошибкой.
- Поддержан файл с одной операцией, с завершающим newline и без него. Preview ограничен 256 KiB.
- Баланс из нескольких строк preview больше не изменяет реальный баланс счёта. Явный программный `currentBalance` сохраняет существующий контракт с проверкой формата.

### Команды и аккаунты

- Удаление команды и выдача роли владельца через приглашение требуют владельца на сервере. Участники по-прежнему могут приглашать обычных участников.
- Проверка роли, последнего владельца и изменение членства выполняются под блокировкой команды. Дубликаты строк одного пользователя не считаются разными владельцами.
- Удаление участника/выход очищают активную команду только при совпадении. Сохранены выход из неактивной команды и удаление владельцем неактивной команды.
- Принятие приглашения атомарно: проверка email, создание членства и потребление приглашения. Повторная обработка не создаёт второе членство; старое приглашение не повышает роль уже существующего участника.
- Удаление аккаунта сначала проверяет все команды. Единственный владелец общей команды должен передать владение; команды с другими участниками не удаляются вместе с профилем.
- В короткой транзакции сохраняется `users.deletion_started_at`, удаляется разрешённое членство и очищается активная команда. Затем Auth вызывается **вне** SQL-транзакции с десятисекундным сигналом отмены.
- Сохраняемый маркер запрещает новое членство/создание команды даже после локального таймаута: отмена HTTP-запроса не доказывает отмену операции на Auth-сервере.
- Повторное удаление разрешено. Ошибки SDK проверяются и в resolved `{ error }`; `user_not_found` допускает идемпотентное завершение. Resend необязателен и не определяет успех удаления аккаунта.
- `/account-deletion` расположен вне sidebar/onboarding gates. После перезагрузки и повторного входа доступна повторная попытка и локальный выход, без создания новой компании.

### Worker и поиск

- Постоянные ошибки используют настоящий BullMQ `UnrecoverableError`; одного сообщения в логе больше недостаточно для остановки повторов. Временные ошибки сохраняют retry.
- Поиск работает без AI-ключа. Опциональная генерация фильтров ограничена двумя секундами, без автоматических provider retries; её отказ не ломает уже выполненный локальный поиск. Ошибки первоначального запроса к БД не скрываются.

## Миграция и развёртывание

- Новый nullable столбец добавлен отдельной CLI-created миграцией `packages/db/self-hosted/upgrades/supabase/migrations/20261031181308_account_deletion_state.sql`.
- SHA-256 применённого bootstrap baseline остаётся `e999657a93946bc8de87cc3a9321757984cfe2e3b3491fa643be58f10b8b32fd`. Offline-проверка фиксирует этот hash и допускает только явное описанное добавление к текущей модели.
- Additive SQL проверен транзакционно на старой disposable БД. После применения `anon` и `authenticated` не имеют UPDATE-доступа к маркеру. Для fixture явно создана отсутствовавшая роль `anon NOLOGIN`, без выдачи привилегий.
- Это проверка SQL и прикладных запросов на PG16, не полная проверка Supabase Auth/RLS. Настоящий Auth cascade в concurrency suite моделируется отдельным DB connection. Новый browser E2E удаления пока не заявлен пройденным.
- Перед обновлением приложения: свежая резервная копия, rehearsal на matched self-hosted stack, применение incremental migration в транзакции и запись в историю миграций. Нельзя переигрывать baseline или запускать Drizzle `push` на рабочей БД.
- Повторный Drizzle `push` на уже подготовленном test fixture обнаружил неоднозначность переименования policy и напечатал non-TTY exception с exit code 0. Этот запуск не считается успешной настройкой. Additive SQL и реальные suites проверены отдельно; clean setup проверяется на новой disposable БД.
- При rollback нельзя возвращать старые membership writers, если остались pending-deletion markers. Маркеры не очищаются автоматически по ошибке/таймауту.
- CLI advisors на тестовом сервере не запускались: установленного CLI там нет. Точечная проверка прав не объявляется полным security/performance audit.

## Что намеренно не считается закрытым

- Точность хранения FX: `exchange_rates.rate` остаётся `numeric(10,2)`. Политика исторических курсов, единое денежное округление и бухгалтерский неттинг возвратов требуют отдельного решения.
- `getCustomerInvoiceSummary` и coverage indicator налогового отчёта не переписаны. В сводке операции без доступной конвертации исключаются; нет нового индикатора полноты всего отчёта.
- Уже ошибочно импортированные суммы/даты автоматически не исправляются. Без bank transaction ID пересекающиеся выписки дают максимальное наблюдаемое число одинаковых fingerprints, а не доказанную глобальную идентичность платежей.
- Импорт остаётся пакетным, не атомарным на весь файл. При поздней ошибке ранние записи остаются; повторный запуск не дублирует их, но durable enqueue/reconciliation обогащения ранее сохранённых строк пока не реализованы.
- Удаление SQL-данных и постановка cleanup job не являются распределённой атомарной операцией. Нужны outbox/reconciliation, очистка внешних подключений одиночных команд и согласованная политика сохранения финансовой истории.
- Новые роли, MFA/session management, полный отказ от Trigger.dev, российские банки/ЭДО/1С, продуктовые письма и локализация не объявляются завершёнными этим пакетом.
- Публичные домены/TLS, настоящий SMTP, provider accounts, off-host backup/restore rehearsal, юридические решения и лицензирование остаются release gates.
- Приостановленный Storage/file-export review не возобновлялся и не включён в этот пакет.
