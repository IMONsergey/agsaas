# AGSaaS: пакет доработок 03

Исходная ревизия: `0a3d12ed398adabd485b096beff234b7c7e903b4`.
Рабочий stage перед этим пакетом: `d95ffa247817c23d855ba178de32bfc987f2c7c1`.
Пакет сохраняет интерфейс и дизайн. Это ограниченный набор проверяемых
изменений, не завершение всего бэклога и не разрешение на публичный запуск.

## Реализовано

1. Резервирование оплаты до обращения к Stripe.
   - Под блокировкой счета сохраняются неизменные сумма в единицах Stripe,
     валюта, компания и connected account. Повтор использует одну reservation
     и один provider key. Внешний HTTP не удерживает SQL-транзакцию.
   - Secret выдается только после условного прикрепления проверенного intent.
     Проверяются актуальное состояние провайдера, metadata, account и сумма.
     Неопределенный retrieve/create не превращается в создание нового intent.
   - Финансовые правки, удаление и ручное повторное открытие защищены с учетом
     reservation и истории платежа. Webhook не доверяет одному invoice ID из
     metadata и не портит чужую reservation при несовпадении привязки.
   - Подтверждение запроса на возврат не равно завершенному возврату. Конечный
     статус требует проверенного результата провайдера. Полный учет частичных
     возвратов и durable provider-event ledger остаются отдельной задачей.
   - Исправлен масштаб Stripe-суммы для UGX; проверяется whole-unit ограничение
     UGX/ISK. Это не утверждение о завершенной поддержке всех валют и лимитов.

2. Устойчивый журнал отправки счетов и напоминаний.
   - До HTTP сохраняется полный неизменный конверт с hash: HTML, ссылки,
     заголовки и PDF. Повторы используют те же байты и provider key.
   - Lease с fencing token разделяет конкурирующих исполнителей. Прием
     провайдером записывается отдельно от локальной атомарной финализации
     статуса счета и активностей. Известный receipt не требует повторного HTTP.
   - Повтор ограничен 23 часами и 12 попытками; обнаруженные clock anomalies
     останавливают новые отправки. Recovery scheduler восстанавливает операции
     после потери Redis-задания, если конверт уже сохранен.
   - SQL-ошибки с параметрами, адресами и PDF не передаются в публичные логи.
     Завершенная операция очищает содержимое конверта, сохраняя receipt/hash.
   - Это не exactly-once delivery и не атомарность первоначального API write
     с Redis enqueue. Операторский workflow сверки еще не реализован.

3. Командные OAuth-приложения и действующее членство.
   - Удаление автора больше не удаляет командное client definition и grants
     других сотрудников. Исторический автор становится `NULL`.
   - Access/refresh validation проверяют действующее членство именно в компании
     токена на primary, pending deletion и активность приложения.
   - Ротация секрета бывшего автора, полный lifecycle revocation/rejoin и
     конкурентная ротация refresh token не объявляются решенными этим FK.

4. Изолированная репетиция восстановления и обновления.
   - Отдельные namespace, порты, bind mounts, volumes и image tags; исходный
     `agsaas-stage` и оба VPN не заменяются. Все входы только loopback.
   - Runtime network изолирована от внешних провайдеров. SMTP используется
     только для capture в Mailpit. Реальные платежи и письма не выполняются.
   - Сохранены PostgreSQL custom dump, приватная конфигурация и ключ pgsodium.
     Ключ проверяется по hash, владельцу и правам, без вывода значения.
   - Реальная репетиция выявила отличие административной роли Supabase,
     отсутствующую ownership role Realtime и наследование лишних default ACL
     при restore в уже инициализированный PG. Процедура учитывает эти условия;
     защитные миграции не ослабляются для обхода несовпадений.
   - Baseline неизменна; upgrades применяются по точному порядку и записывают
     совместимую CLI историю в одной транзакции с ограничением блокировок.
   - Отдельный opt-in account smoke получает настоящую сессию через SMTP OTP,
     создает только собственный пустой аккаунт/команду, вызывает `user.delete`
     и раздельно проверяет Auth `user_not_found`, отсутствие профиля с еще
     действительным JWT и API `NOT_FOUND`. Его offline tests не подменяют
     фактический запуск на стенде.

## Проверки

Реальное same-host восстановление завершено на отдельной копии:
инвентарь данных совпал, а полная сверка прав/RLS по 2 058 объектам, 32 ролям,
25 членствам и 27 default-ACL entries не обнаружила отличий. Ключ pgsodium
сохранен и проверен. До применения точечных исправлений выполнялись
rollback-only пробы. Это подтверждает именно описанный пустой по финансовым
данным снимок, не восстановление большого production-набора.

Итоговые результаты фиксируются после завершения проверок для опубликованной
ревизии в этом отчете и [Draft PR #1](https://github.com/IMONsergey/agsaas/pull/1).
Наличие PostgreSQL-тестов в дереве и локальные skip не считаются выполнением
SQL. Offline provider tests используют настоящий SDK с перехваченным HTTP,
а не реальные операции Stripe/Resend.

## Границы репетиции и оставшиеся работы

- Снимок stage содержит 3 профиля, 3 компании, 0 счетов, 0 транзакций и
  0 Storage objects. Он не доказывает производительность миграций на большом
  объеме, восстановление непустого Storage или исторических финансовых данных.
- Backup находится на том же сервере. Это не off-host/PITR и не полная копия
  `_supabase`, Redis/AOF, object bytes и всего сервера.
- Сохранение master key не подменяет roundtrip всех видов зашифрованных
  пользовательских данных. Доступы и резервные копии остаются приватными.
- Публичные домены, HTTPS, production SMTP, банковские/платежные/AI аккаунты,
  Storage/export WIP, полное browser E2E и юридические решения остаются gates.
- Нет бесконечной идемпотентности провайдера. Неизвестный исход после окна
  требует сверки; нельзя заменить ключ или обнулить время, чтобы повторить HTTP.
- При переключении старых workers необходим drain/reconcile. Старые задания
  не приобретают историю внешнего успеха задним числом.
- Shared-team invitation/last-owner HTTP smoke не выполнен: текущая отправка
  приглашений зависит от Trigger.dev. Это отдельный путь для перевода на
  собственную очередь и проверки доставки, без обхода через admin sessions.
